# تحديث تكامل API - إزالة الأسماء المحلية

## التغييرات المطبقة

### 1. إزالة الأسماء المحلية الثابتة

تم إزالة جميع الأسماء المحلية الثابتة من:

- `course-category.component.ts`
- `homepage.component.ts`
- `selected-courses.component.ts`

### 2. إنشاء خدمة جديدة لأسماء الفئات

**ملف جديد**: `category-names.service.ts`

- محاولة الحصول على أسماء الفئات من API مخصص (`/api/Categories`)
- fallback إلى API الكورسات الحالي (`/api/Course/categories`)
- إنشاء أسماء عامة بناءً على `categoryId`

### 3. تحديث خدمة الفئات الرئيسية

**ملف محدث**: `category.service.ts`

- استخدام الخدمة الجديدة لأسماء الفئات
- إزالة الأسماء المحلية الثابتة

### 4. تحديث مكون الفئات

**ملف محدث**: `course-category.component.ts`

- استخدام الخدمة الجديدة
- نظام fallback متعدد المستويات
- تسجيل مفصل في console

## نظام Fallback الجديد

```
1. محاولة /api/Categories (API مخصص للفئات)
   ↓ (إذا فشل)
2. استخدام /api/Course/categories مع أسماء عامة
   ↓ (إذا فشل)
3. استخدام أسماء عامة: "فئة 1", "فئة 2", إلخ
```

## الأسماء العامة المستخدمة

```typescript
const genericNames = ['فئة الإرشاد السياحي', 'فئة إدارة الفنادق', 'فئة السياحة', 'فئة الضيافة', 'فئة الطيران والسفر', 'فئة الدعم والمهارات', 'فئة تقنية'];
```

## المزايا

1. **مرونة أكبر**: النظام يحاول عدة مصادر للحصول على الأسماء
2. **لا توجد أسماء ثابتة**: جميع الأسماء تأتي من API أو أسماء عامة
3. **سهولة الصيانة**: إضافة فئات جديدة لا تتطلب تحديث الكود
4. **تسجيل مفصل**: يمكن تتبع مصدر الأسماء في console

## التوصيات المستقبلية

1. **إنشاء API مخصص للفئات**:

   ```
   GET /api/Categories
   Response: [
     { "id": 1, "name": "Tourism Guiding", "nameAr": "دورات الإرشاد السياحي" },
     { "id": 2, "name": "Hotel Management", "nameAr": "دورات إدارة الفنادق" }
   ]
   ```

2. **تحديث API الكورسات**:
   ```
   GET /api/Course/categories
   Response: [
     {
       "id": 6,
       "category": "دورات الإرشاد السياحي",  // ← إضافة اسم الفئة
       "categoryId": 1,
       "course": "مقدمة في الإرشاد السياحي",  // ← إضافة اسم الكورس
       "courseId": 3
     }
   ]
   ```

## اختبار النظام

1. تحقق من console logs لمعرفة مصدر الأسماء
2. تأكد من عمل النظام مع API الحالي
3. اختبر fallback عند فشل API

## حالة النظام الحالية

✅ **يعمل مع API الحالي**
✅ **لا توجد أسماء ثابتة في الكود**
✅ **نظام fallback متعدد المستويات**
✅ **تسجيل مفصل للأخطاء**
